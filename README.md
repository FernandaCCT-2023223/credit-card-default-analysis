# Credit Card Default Analysis

## Project Overview

This project explores customer characteristics and financial behaviours that may be associated with credit card default. It uses the *Default of Credit Card Clients* dataset from the UCI Machine Learning Repository.

The analysis was done in R and includes data inspection, cleaning, exploratory data analysis (EDA), categorical variable encoding and Principal Component Analysis (PCA).

## Research Question

**What customer characteristics and financial behaviours are associated with credit card default?**

## Dataset

- **Name:** Default of Credit Card Clients
- **Source:** [UCI Machine Learning Repository](https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients)
- **Project Domain:** Economy and Finance
- **Number of records:** 30,000
- **Explanatory features:** 23
- **Original columns:** 25, including the customer ID and target variable
- **Target variable:** `default.payment.next.month`
  - `0` = No default
  - `1` = Default

The dataset includes information about credit limits, age, education, marital status, repayment status, bill amounts and payment amounts. According to the UCI repository, it contains no missing values.

The dataset is licensed under the Creative Commons Attribution 4.0 International (CC BY 4.0) licence.

**DOI:** [10.24432/C55S3H](https://doi.org/10.24432/C55S3H)

## Analysis Workflow

### 1. Initial Data Inspection

The dataset is inspected to understand its structure, dimensions, variables, missing values, duplicated records and unique category values.

### 2. Data Quality Checks and Cleaning

Potential outliers, unusual category codes and negative financial values are investigated.

The cleaning process includes:

- Grouping unusual `EDUCATION` values (`0`, `5` and `6`) into category `4` (others).
- Grouping `MARRIAGE` value `0` into category `3` (others).
- Retaining IQR outliers after inspection rather than automatically removing them.
- Retaining negative bill amounts because they may represent credit balances or other account adjustments.

A copy of the original data is kept before cleaning.

### 3. Exploratory Data Analysis (EDA)

The analysis explores relationships between default status and customer or financial variables, including:

- Education, marital status and sex.
- Credit limits and customer age.
- Previous repayment status.
- Bill amounts and payment amounts.
- Correlations between monthly bills and payments.
- Payment behaviour across the six recorded months.

Tables, summary statistics and visualisations are used to explore these patterns.

### 4. Categorical Variable Encoding

A binary variable is created for sex, while one-hot encoding is applied to education and marital status. Repayment status variables are kept numeric because they represent ordered categories.

The encoded dataset is saved in `data/processed/credit_card_encoded.csv`.

### 5. Principal Component Analysis (PCA)

PCA is applied to the encoded explanatory variables. The customer ID, target variable and one reference category from each one-hot encoded group are excluded from the PCA input.

The variables are centred and scaled because they use different measurement units.

The analysis examines explained variance, cumulative variance, component loadings and variable contributions. A scatterplot of the first two principal components is also used to explore the distribution of customers by default status.

## Important Notes

- All findings and interpretations should be based on the actual output produced by running the R script.
- Correlation and observed associations do not establish causation.
- PCA is used for exploratory dimensionality reduction and does not by itself predict credit card default.
